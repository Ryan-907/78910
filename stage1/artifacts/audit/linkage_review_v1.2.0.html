Filtering something out is the dangerous direction. If you mark a detection third_party or organizational, that information type leaves the inventory and the future gate check can never govern it. The document is released, the recipient holds a type they should not, the decision looks correct, and nothing records that it happened. A wrong subject call only causes an over-block, which is visible and correctable. When genuinely torn, prefer subject or ambiguous over filtering.
For each highlighted occurrence, whose attribute is it?
subject - about this document’s data subject (named in the document header below)
third_party - about some other individual: a signing clinician, a relative, a colleague
organizational - belongs to the institution rather than any individual: clinic address, facility NPI, main phone, statutory notice
ambiguous - not decidable from what is shown. A real answer; use it rather than guessing.

Remember the employment inversion: where subject_type is employee or contractor, the subject IS staff, so a clinician’s name, job title, licence and salary are subject.

Record answers in linkage_sheet_v1.2.0.csv, in the true_class column, matched by row_id. Then run python -m stage1.score_linkage.
